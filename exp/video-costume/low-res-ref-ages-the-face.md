## 场景

用户给三张微信真人照做同框定妆，`gptimg edit -f high -q high -s 1024x1536` 逐人出正面定妆照。
三张原照分辨率差别很大：left 是 1024×1820，mid 是 416×551，right 是 537×718。

## 结论

**参考照短边小于约 600px 时，prompt 里必须显式加一段「年龄铁律」**，否则模型在把低分图
放大补细节的过程中会往脸上填皱纹，把二十多岁做成三十多岁。骨相是对的、像的，就是老了十岁，
所以很容易误判成"不像"而去反复重出脸型，方向全错。

可直接复用的段落：

```
【年龄铁律】她是二十多岁的年轻女生，皮肤紧致光滑有弹性。绝对不要把她画老：
不要加皱纹、不要加法令纹、不要加眼袋、不要加泪沟、不要加颈纹、
不要让皮肤松垂、不要让脸色发黄发暗。
```

同时补一条发丝约束，低分图放大还会把头发补成大量细碎乱翘的发丝，显得毛躁也加重年龄感：
「发丝整齐顺滑贴合头型，不要画出大量细碎乱翘的发丝、不要毛躁」。

判定口径：拿到参考照先 `sips -g pixelWidth -g pixelHeight` 量一下，短边 < 600px 就默认加这两段。

## 证据

同一批三次调用、同一套 prompt 模板、只有参考照不同：

- left（1024×1820）→ 一版通过，脸年轻、像度好，无需年龄锚点
- mid（416×551）→ v1 出来约三十五岁，有明显法令纹、眼袋、皮肤发暗；加年龄铁律后 v2 通过
- right（537×718）→ v1 同样显老，且额前被补出大量细碎乱翘发丝；加年龄铁律+发丝约束后 v2 通过

三次都是 `-f high -q high`，`-f high` 保住了骨相，老化发生在皮肤和发丝的细节补全环节，
不是骨相跑了。

## 反例

看到 v1 觉得"不像"，于是去改脸型描述、加"不要瘦脸""沿用脸型骨相"——白改，因为骨相本来就对。
真正的偏差在年龄维度。误判方向会连着浪费好几次 `-q high` 的调用额度。
