## 场景

要做二创换人，把原片里的人换成一个真实存在的人。先按 `video-costume` 第 6 节
「真人照过不了审」的结论，判定这条路只能走本地 ComfyUI，后来实测推翻了。

## 结论

**真人脸能不能用，取决于走哪条通道，不是一刀切。**

| 通道 | 真人脸 | 说明 |
|---|---|---|
| 即梦网页版 / `dreamina` CLI | ❌ | 写实人脸前置审核直接拦 |
| 火山 Seedance 2.0/2.5 | ❌ | 文档写明不支持含真人脸的参考图/视频 |
| 即梦/豆包 **APP**「真人出镜」 | ✅ 仅本人 | 需录音录像活体校验生成数字分身，**只能 APP 里人工做，CLI 用不上** |
| **百炼 animate API（`bvid swap`）** | ✅ **放行** | 实测真人照片直接出片 |
| 本地 ComfyUI | ✅ | 无平台审核 |

→ **本地 ComfyUI 现在只剩两个理由：不想按秒付费、要改模型细节。** 不再是真人脸的唯一出路。

注意「是不是本人」平台默认不知道。即梦拦的是**无法证明授权的真人脸**，所以它的
解法是活体认证；百炼 animate 这条则根本没有这道前置人脸闸。两种设计别混为一谈。

`video-costume` 第 6 节那张表依然成立，但它只管**即梦/火山的出图与生视频环节**，
不要推广到所有通道。已在该 skill 加了交叉引用。

## 证据

`bvid swap --image <真人照> --video <驱动视频> --model wan2.2-animate-mix --mode wan-std`：

- 真人半身自拍 1024×1820 → `task_status: SUCCEEDED`，正常出片，3.00 元
- 真人全身照 296×583（婚礼抓拍，多人同框）→ `SUCCEEDED`，正常出片，3.00 元

两次都**没有**报 `DataInspectionFailed`（内容安全拦截），也没有报
`IPInfringementSuspect`（侵权嫌疑）。官方 API 文档对真人脸是否允许没有任何表述，
只说输入输出会过内容安全审核，所以这个结论只能靠实测拿到。

身份迁移质量也好：眼镜、圈形耳环、卷短发、项链、条纹吊带全部迁移，脸认得出是同一个人。

## 反例

- ❌ 看到 `video-costume` 的「真人照过不了审」就断定换人必须本地跑——通道不同结论不同
- ❌ 以为在即梦 APP 做完活体认证，`dreamina` CLI 就能传真人照了——认证解锁的是 APP 内
      的分身功能，CLI 走网页/API 通道，照样传不了
- ❌ 把「API 放行」当成「法律上没问题」——**放行只是技术闸，肖像权和标识义务一条不少**：
      换别人必须有明确授权；AI 生成标识要做显著位置 + 元数据两层；原片著作权还在原权利人手里
